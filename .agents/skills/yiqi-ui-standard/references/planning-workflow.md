# UI 规划工作流

## 适用条件

在以下任一条件满足时使用本工作流：

- 用户选择“规划与需求”。
- 用户明确处于立项/PRD/需求讨论，且未进入代码实现。

## 硬规则

1. 不询问技术栈。
2. 不生成代码。这里的“不生成代码”是指不生成面向产品交付或运行的生产实现代码。
3. 每次只确认一个决策。
4. 先产品画像后页面结构。
5. 用户批准书面规范前，不进入代码实现。

## 访谈顺序

严格按以下顺序推进；每次只确认当前一项：

1. 目标用户与场景
2. 主要任务
3. 主类型和 0–3 次类型
4. 页面地图
5. 密度与节奏
6. 内容与真实素材
7. Hero
8. 实体暗色/液态玻璃
9. 响应式平台
10. 可访问性风险状态

## 默认交付物

输出一份完整 UI 需求规范，至少包含：

- 产品画像与页面分类
- 页面地图与信息层级
- 核心工作流
- 页面结构与布局
- 组件状态矩阵
- 字体、卡片、主题与动效规则
- 响应式要求
- 真实素材清单
- 验收标准

## 可视化决策

需要比较结构方案时，在浏览器中展示 2–3 个布局方向。所有方向使用真实业务内容，不使用无意义占位图形。

为完成可视化决策，允许创建隔离的临时浏览器决策稿。临时稿不得进入产品源码，临时稿不得绑定技术栈；用户批准后应丢弃或重新实现。

## 批准门槛

进入代码实现前必须依次完成：

1. 将已确认决策写入完整规范。
2. 扫描占位符、矛盾和模糊要求并消除问题。
3. 请用户审阅完整规范。
4. 获得用户明确批准后，才能进入代码实现。
