# Hero 与 No Hero 规范

## 路由原则

同时判断当前页面主要任务和页面类型，自动选择 Hero 或 No Hero；冲突时遵循 `references/product-archetypes.md` 的优先级，当前页面主要任务优先于页面类型。允许用户覆盖。持续操作、数据或任务壳层默认使用 No Hero。

允许 Hero 的页面包括品牌官网、产品介绍、发布页面和部分低密度服务页。

部分低密度服务页仅在主要任务为浏览、理解或咨询转化，且低信息密度、非持续工作、无数据管理或批量操作壳层时允许 Hero。若存在持续任务、数据或操作，则使用 No Hero。

## Approved Hero

Approved Hero 仅限以下三类：

1. 真实产品或对象的全幅媒体。
2. 可检查的产品界面或工作状态。
3. 编辑式内容构图，并配合实际成果、流程或证据。

## 标题范围

- 桌面 H1 使用 36–42px，移动 H1 使用 30–36px。
- H1 使用品牌、产品名或明确服务类别。
- 同一视口不连续出现多个 H1。
- 字号不得随视口无限放大。

## 首屏要求

- 品牌或产品必须成为第一信号。
- 首屏必须露出下一业务内容。
- 主要视觉承载产品、服务过程或真实状态。
- Web 中真实 Hero 媒体使用 `data-ui-hero-media`，可检查状态使用 `data-ui-product-state`。
- 无真实素材时采用内容主导的构图，并输出素材需求。

## 禁止

- 禁止默认左右文案/装饰图分栏。
- 禁止大型抽象圆形、轨道、光球和无信息几何。
- 禁止装饰图冒充产品视觉。
- 禁止把 Hero 主内容放进装饰卡片。
- 禁止用超大标题和大空白代替层级。

## No Hero 默认页面

以下页面默认使用 No Hero：

- SaaS 工作台
- AI 持续操作工具
- 管理后台
- 数据分析和监控页面
- 表格/审批/项目/批量操作页面
- 个人中心/钱包/账户操作页面

No Hero 页面直接显示导航、当前任务、数据、状态和主要操作。
