# MVP 核心功能范围（修订版）

## 产品定位

**核心定位：** 企业员工协作管理平台 + AI 全员助手

**市场差异化：**
- **vs WorkBuddy/豆包：** 他们只有 AI 能力，我们有完整的企业组织管理
- **vs 钉钉/飞书/企业微信：** 他们只有协作管理，AI 能力弱，我们深度融合
- **独特价值：** AI 能力 + 企业管理系统深度集成，让 AI 真正融入组织架构和工作流程

**一句话描述：**
> 一个自带完整企业管理系统的 AI 工作平台，为每位员工提供智能工作助手，串联企业工作流程

---

## 核心卖点（按重要性排序）

### 🏆 第一核心：完整的企业协作管理系统
- 组织架构管理（公司 → 部门 → 团队）
- 任务协作和流转（上下级派发、跨部门协同）
- 基于角色的权限体系
- 多租户 SaaS 架构

### 🤖 第二核心：全员 AI 工作助手
- 每个员工都有 AI 助手（角色感知、权限感知）
- AI 融入工作流程（任务扩写、知识问答、文档生成）
- 对标 WorkBuddy/豆包 的 AI 能力

### 🔗 第三核心：工作流程串联
- 任务关联和依赖
- 跨部门协作（手动触发，Phase 2 自动化）
- 企业知识沉淀和复用

## 一、功能优先级排序

### P0 级别（企业协作基础设施 - 核心中的核心）

#### 1. 多租户系统
**优先级：** P0  
**原因：** SaaS 架构的基础，支持多个企业独立使用

**核心能力：**
- 租户注册和配置管理
- 数据完全隔离（基于 tenant_id）
- 租户上下文自动注入
- 租户级别的定制化（logo、主题色、功能开关）

**验收标准：**
- [ ] 可以创建多个租户，数据 100% 隔离
- [ ] 每个 API 请求自动携带租户上下文
- [ ] 租户 A 无法访问租户 B 的任何数据
- [ ] 支持租户配置（公司名称、logo、主题色）

**不包括（留待后续）：**
- 复杂的资源配额和限流
- 细粒度的功能开关
- 租户间数据共享

---

#### 2. 组织架构管理
**优先级：** P0  
**原因：** 企业协作的核心，定义"谁属于哪个部门、谁管理谁"

**核心能力：**
- 公司/部门/团队的层级结构（树形）
- 员工归属关系（一个员工可以属于多个部门）
- 上下级汇报关系（部门负责人）
- 组织架构可视化（组织树）

**验收标准：**
- [ ] Admin 可以创建部门层级（如：公司 → 销售部 → 华东区 → 上海组）
- [ ] 可以指定部门负责人
- [ ] 员工可以查看自己所属的部门和上级
- [ ] 支持员工跨部门（如：既属于销售部，也属于某个项目组）

**示例组织结构：**
```
某科技公司
├── 销售部
│   ├── 华东区（负责人：张经理）
│   │   ├── 上海组
│   │   └── 杭州组
│   └── 华南区
├── 研发部（负责人：李经理）
│   ├── 前端组
│   ├── 后端组
│   └── 测试组
└── 财务部
```

**不包括（留待后续）：**
- 复杂的矩阵式组织结构
- 虚拟团队（跨部门项目组）
- 组织变更历史记录

---

#### 3. 用户认证和权限
**优先级：** P0  
**原因：** 安全和访问控制的基础

**核心能力：**
- 用户注册、登录（密码认证）
- JWT token 生成和验证
- 基于角色的权限控制（RBAC）
- 三个核心角色：
  - **Admin（管理员）**：管理整个租户（组织架构、用户、全局配置）
  - **Manager（经理）**：管理所属部门（成员、任务、部门数据）
  - **Member（员工）**：使用系统（自己的任务、AI 助手、知识库）

**验收标准：**
- [ ] 用户可以注册和登录
- [ ] Admin 可以：
  - 创建和管理组织架构
  - 添加/删除/编辑用户
  - 查看所有任务和数据
- [ ] Manager 可以：
  - 管理自己部门的成员
  - 给下属派发任务
  - 查看部门内的所有任务
- [ ] Member 可以：
  - 查看和完成自己的任务
  - 使用 AI 助手
  - 查询知识库

**权限矩阵示例：**

| 资源 | Admin | Manager | Member |
|-----|-------|---------|--------|
| 组织架构 | 增删改查 | 只读 | 只读（自己部门）|
| 用户管理 | 增删改查 | 本部门增删改查 | 只读（自己）|
| 任务管理 | 全部 | 本部门全部 | 自己的任务 |
| 知识库 | 全部 | 本部门 | 有权限的文档 |

**不包括（留待后续）：**
- OAuth 第三方登录（飞书、企业微信）
- 细粒度的资源级权限
- 多因素认证

#### 4. 任务管理和协作
**优先级：** P0  
**原因：** 企业协作的核心场景，工作流程的载体

**核心能力：**

**4.1 任务基础功能**
- 任务 CRUD（创建、查看、编辑、删除）
- 任务分配（单人/多人负责）
- 任务状态流转（todo → in_progress → review → done）
- 任务优先级（低、中、高、紧急）
- 任务截止日期和提醒
- 任务标签和分类

**4.2 协作场景（核心）**

**场景 A：上下级任务派发**
```
1. 领导（Manager）创建任务
2. 分配给下属（Member）
3. 下属接受任务并开始执行
4. 下属标记为"待审核"
5. 领导审核并标记为"已完成"
```

**场景 B：跨部门协作**
```
1. 销售部创建任务"客户 A 签约项目"
2. 手动创建关联任务：
   - 研发部："开发客户 A 的定制功能"
   - 财务部："为客户 A 开具发票"
3. 各部门可以看到关联任务
4. 任务完成顺序有依赖关系（销售完成 → 研发开始）
```

**场景 C：子任务拆解**
```
1. 经理创建主任务："完成 Q1 销售目标"
2. 拆解为子任务：
   - 子任务 1：开发 10 个新客户（分配给张三）
   - 子任务 2：维护 20 个老客户（分配给李四）
   - 子任务 3：完成 50 万业绩（分配给王五）
3. 所有子任务完成后，主任务自动标记为完成
```

**4.3 任务视图**
- 看板视图（Kanban）：按状态分列（待办、进行中、已完成）
- 列表视图（List）：按部门、负责人、优先级筛选
- 日历视图（Calendar）：按截止日期展示

**4.4 任务通知**
- 任务被分配时通知负责人
- 任务状态变更时通知创建者
- 任务即将到期时提醒负责人

**验收标准：**
- [ ] Manager 可以创建任务并分配给本部门或其他部门的成员
- [ ] 支持任务依赖关系（任务 B 必须等任务 A 完成后才能开始）
- [ ] 支持子任务（主任务下有多个子任务）
- [ ] 任务看板视图（按状态分列：待办、进行中、已完成）
- [ ] 任务列表视图（按部门、负责人、优先级筛选）
- [ ] 任务关联（销售任务关联研发任务、财务任务）
- [ ] 任务到期提醒（截止日期前 1 天提醒）
- [ ] 任务状态变更通知（分配、完成、审核）

**关键指标：**
- 领导可以看到所有下属的任务进度
- 员工可以看到自己的待办任务（按优先级和截止日期排序）
- 跨部门任务可以明确看到关联关系和依赖

**不包括（留待后续）：**
- 甘特图
- 燃尽图
- 工时统计报表
- 自动化工作流（触发器 + 动作）

### P1 级别（AI 增强能力 - 差异化竞争力）

#### 5. 全员 AI 工作助手
**优先级：** P1  
**原因：** 对标 WorkBuddy/豆包，让 AI 融入每个员工的工作流程

**核心能力：**

**5.1 AI 对话助手**
- 每个员工都有独立的 AI 对话窗口
- AI 能感知用户角色和权限（销售员工 vs 研发员工）
- AI 能访问用户有权限的企业数据
- 支持多轮对话和上下文理解

**5.2 AI 增强的任务管理**
- **任务智能扩写**：领导输入简短描述 + 关键词，AI 自动生成详细任务描述、子任务拆解、推荐负责人
- **任务建议**：AI 根据历史数据建议任务优先级、预估工时
- **进度提醒**：AI 主动提醒即将到期的任务

**5.3 AI 文档生成**
- 根据对话生成 Word 文档（会议纪要、客户邮件、报告）
- 根据数据生成 Excel 报表
- 根据要点生成 PPT 演示文稿
- 自动应用企业 branding（logo、颜色、模板）

**5.4 AI 知识问答**
- 基于企业知识库的智能问答
- 权限感知（不同用户看到不同文档）
- 引用来源标注（回答来自哪份文档）
- 跨文档综合回答

**验收标准：**
- [ ] 每个员工登录后可以与 AI 对话
- [ ] AI 能理解用户角色（销售员工问销售问题，研发员工问技术问题）
- [ ] 任务扩写功能：
  - 输入：标题 + 关键词
  - 输出：详细描述 + 子任务列表 + 推荐负责人
  - 生成时间 < 5 秒
- [ ] 文档生成：
  - 对话式生成 Word/Excel/PPT
  - 自动应用企业模板
  - 生成的文档可下载并关联到任务
- [ ] 知识问答：
  - 用户提问 → AI 检索知识库 → 返回答案 + 引用来源
  - 响应时间 < 3 秒
  - 准确率 > 75%（基于测试问题集）

**对标参考：**
- **WorkBuddy**：100+ AI 专家、端到端任务交付
- **豆包工作**：多 Agents 并行、与飞书深度集成
- **我们的差异化**：AI + 完整的企业组织管理系统

**不包括（留待后续）：**
- 预设的专业 AI 助手（销售助手、研发助手、财务助手）
- AI 主动工作（自动发现问题并处理）
- 多模态输入（语音、图片）

---

#### 6. 企业知识库
**优先级：** P1  
**原因：** 企业知识沉淀，AI 问答的数据基础

**核心能力：**
- 上传企业文档（PDF、Word、Markdown、TXT）
- 文档自动解析、分块、向量化
- 向量数据库存储（Milvus/Pinecone）
- 语义检索（RAG）
- 权限控制（部门级、用户级）

**验收标准：**
- [ ] Admin 可以上传文档到知识库
- [ ] 支持按部门组织文档（销售部文档、研发部文档）
- [ ] 文档自动向量化存储
- [ ] 支持全文搜索和语义搜索
- [ ] 权限控制：
  - 公开文档：所有人可见
  - 部门文档：只有部门成员可见
  - 私有文档：只有上传者可见
- [ ] AI 问答时自动检索相关文档

**不包括（留待后续）：**
- 文档多人协同编辑
- 文档版本控制
- 文档评论和讨论
- 多模态文档（图片、视频、音频）

## 二、MVP Demo 演示场景

### 场景：「销售团队使用 AI 助手管理客户跟进」

**角色：**
- 销售经理（Manager）
- 销售员工（Member）

**演示流程：**

#### Step 1: 销售经理创建任务
```
1. 登录系统（角色：Manager）
2. 进入任务管理页面
3. 点击「新建任务」
4. 输入：
   - 标题：跟进客户 A 的采购需求
   - 关键词：价格谈判、合同审核、预算 50 万
   - 负责部门：销售部
5. 点击「AI 自动扩写」
6. AI 生成：
   - 详细任务描述
   - 5 个子任务
   - 推荐负责人：张三
   - 预估工时：8 小时
7. 经理审核并点击「确认分配」
```

#### Step 2: 销售员工查看任务
```
1. 员工张三登录系统
2. Dashboard 显示新任务通知
3. 查看任务详情和子任务列表
4. 开始第一个子任务：「调研客户背景」
```

#### Step 3: 员工向知识库提问
```
1. 在任务详情页点击「AI 助手」
2. 提问：「如何应对客户的价格异议？」
3. AI 检索知识库文档（《销售手册》《客户谈判技巧》）
4. 返回结构化答案 + 引用来源
5. 员工点击引用查看原文档
```

#### Step 4: 生成客户跟进邮件
```
1. 员工继续对话：「根据这些建议，帮我生成一份客户跟进邮件」
2. AI 生成 Word 文档
3. 文档应用企业模板（公司 logo、签名）
4. 员工下载文档
5. 文档自动关联到当前任务（作为附件）
```

#### Step 5: 完成任务
```
1. 员工标记子任务为「已完成」
2. 所有子任务完成后，标记主任务为「已完成」
3. 经理在 Dashboard 收到完成通知
4. 查看任务详情和附件（生成的邮件）
```

## 六、风险和应对

### 风险 1：AI 扩写质量不稳定
**影响：** 核心卖点无法展示  
**应对：**
- 预先准备 prompt 模板库
- 建立评估数据集（100 个测试任务）
- 设置人工审核兜底机制

### 风险 2：向量数据库部署复杂
**影响：** 知识库功能延期  
**应对：**
- 使用云服务（Pinecone）而非自建 Milvus
- 准备降级方案（全文检索代替语义检索）

### 风险 3：Web UI 开发进度慢
**影响：** Demo 无法完整演示  
**应对：**
- 前期使用 CLI 验证后端功能
- 采用组件库（Ant Design / shadcn/ui）加速开发
- 降低 UI 美观度要求（功能优先）

### 风险 4：多租户数据隔离出现漏洞
**影响：** 安全问题，无法交付  
**应对：**
- 在架构设计阶段充分评审
- 编写自动化测试覆盖所有跨租户场景
- 引入代码审查和渗透测试
