# 科研数据分析计划

## 目标

在实际分析前明确数据、问题、质量标准、处理步骤、交付物和复现要求，降低拿到数据后反复试错和选择性分析的风险。

## 工作流程

1. 定义分析目标、决策问题、数据所有者、使用权限和最终交付物。
2. 建立数据清单：来源、格式、粒度、时间、主键、单位、编码和版本。
3. 设计数据接收与完整性检查，包括哈希、行列数、范围、重复和关联完整性。
4. 规划质控与清洗：缺失、异常、批次、单位、时间对齐和派生变量。
5. 区分探索性、验证性和预测性分析，分别定义评价标准。
6. 规划训练验证拆分、交叉验证或独立验证，防止数据泄漏。
7. 列出统计或计算方法、输入输出、软件环境和资源需求。
8. 设计图表、表格、代码、日志、数据字典和复现包的交付结构。
9. 设置中止点：数据质量不足、样本不独立、关键字段缺失或权限不清时停止。

## 输出格式

- **目标与决策用途**。
- **数据资产清单与字段需求**。
- **质控和清洗规则**。
- **分析阶段与依赖关系**。
- **验证、敏感性和泄漏防控**。
- **计算环境与代码草稿需求**。
- **交付物、版本和复现要求**。
- **风险、停止条件和待确认问题**。

## 质量检查

- 不把计划写成已执行结果。
- 原始数据与处理后数据分离，所有变换可追踪。
- 数据质量门槛先于复杂模型。
- 涉及敏感数据时说明去标识化、访问控制和最小必要使用。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
