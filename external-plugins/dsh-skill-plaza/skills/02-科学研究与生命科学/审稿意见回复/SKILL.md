# 审稿意见回复

## 目标

将审稿意见转化为可执行修订任务，并起草尊重、清晰、证据充分的逐点回复。任何实验、分析或文本修改只有在确实完成后才能使用完成时表述。

## 工作流程

1. 原样整理每条审稿意见，拆分其中多个要求。
2. 分类为：同意并修改、部分同意、需要澄清、无法完成但可补充限制、基于误解需改进表达。
3. 评估每项要求对主张、方法、数据和篇幅的影响。
4. 为每条意见制定行动：修改位置、补充证据、分析草稿、解释理由或调整结论。
5. 起草回复：感谢与复述理解、直接回答、说明具体改动、给出页码行号占位策略；没有最终版页码时不要伪造。
6. 对不同意的意见，用证据和范围边界解释，不攻击审稿人。
7. 建立修订追踪表，检查回复信、稿件和补充材料一致。

## 输出格式

- **总体回复开场**。
- **逐条回复**：审稿意见、响应立场、拟采取行动、回复草稿、修订位置待填项。
- **新增工作清单**。
- **无法完成事项及替代处理**。
- **一致性检查清单**。

## 质量检查

- 未完成的实验或分析使用计划时态，不写成已完成。
- 不虚构页码、行号、统计结果或新增引用。
- 回复正文直接回答问题，不只写“已修改”。
- 若修改改变主要结论，提醒同步更新摘要、讨论和图表。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
