# 论文同行评审

## 目标

以公平、具体、可执行的方式评估稿件能否支持其主要主张，并帮助作者改进。只评价可见材料；无法核验的数据、代码或引用必须明确说明。

## 工作流程

1. 总结研究问题、方法、主要结果和作者主张，确认理解无误。
2. 先评估重要性与新意，再评估设计、样本、测量、分析、可复现性和伦理报告。
3. 检查结论是否超出研究设计和证据，尤其关注因果、普遍性和临床意义。
4. 将意见分为重大问题、次要问题和编辑性建议。
5. 每个重大问题说明：观察到什么、为何重要、需要什么证据或修改。
6. 区分“必须修正才能支持结论”和“可选的扩展研究”，避免要求无限新增实验。
7. 标记无法完成的核验，如原始数据、代码、注册记录或引用真实性。

## 输出格式

- **总体评价**。
- **稿件贡献摘要**。
- **重大问题**：编号、证据位置、影响、建议。
- **次要问题**。
- **透明度与复现性检查**。
- **结论边界**。
- **给编辑的保密意见**（仅用户明确需要时）。

## 质量检查

- 不因不喜欢研究结论而否定方法合格的研究。
- 不使用侮辱性、身份化或含糊语言。
- 不声称检查了未提供的补充材料、数据或引用。
- 建议与稿件目标成比例，并保留作者合理选择空间。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
