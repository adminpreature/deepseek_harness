# 生物信息学分析方案

## 目标

把生物学问题和组学数据需求转化为可实施、可复现的分析计划。适用于方案设计、工具选择和交付规范，不在没有执行环境与数据时声称完成分析。

## 工作流程

1. 明确生物学问题、物种、样本设计、实验平台、数据类型和主要终点。
2. 建立输入数据清单：原始格式、参考版本、注释版本、样本表、批次、配对和协变量。
3. 规划原始数据质控、污染检查、接头或低质量处理、比对或定量及阶段性质量门槛。
4. 规划样本级质控、异常样本规则、批次评估和可视化。
5. 根据问题设计统计比较、协变量、重复测量、多重检验和效应量报告。
6. 规划功能解释、富集或网络分析，并防止背景集选择和循环论证。
7. 设计独立验证、实验验证或外部队列验证。
8. 记录软件、版本、参数、参考数据、随机种子、资源和容器化建议。
9. 若涉及 RNA-seq、单细胞或大型基因组数据，只提供相应流程计划与代码草稿，明确未实际计算。

## 输出格式

- **研究问题与设计摘要**。
- **输入数据、元数据和参考版本需求**。
- **分阶段流程图**：输入、工具候选、参数依据、输出、质控门槛。
- **统计与验证计划**。
- **复现环境和资源估算**。
- **交付物清单**。
- **风险、停止条件与未执行声明**。

## 质量检查

- 不根据文件名猜测物种、参考版本或实验设计。
- 不把软件默认参数当作普遍最优。
- 明确生物学重复、批次和混杂。
- 不虚构运行日志、质控图、差异基因或富集结果。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
