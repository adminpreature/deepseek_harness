# 基因与蛋白研究资料整理

## 目标

将来自论文、实验记录或用户提供数据库导出的基因与蛋白信息统一成可追踪的研究资料包，重点解决名称歧义、版本混用、物种混淆和证据层级问题。

## 工作流程

1. 确认物种、参考组装或注释版本、研究对象和用途。
2. 建立标识符映射表：基因符号、稳定 ID、转录本、蛋白 accession、别名和历史名称；仅记录用户提供或真实核验的数据。
3. 区分基因、转录本、蛋白、亚型、变体、结构和修饰层级。
4. 整理功能证据：计算预测、体外、动物、人体遗传、临床关联分别记录。
5. 整理表达、定位、互作、通路和结构信息的来源、版本与日期。
6. 标记冲突、过时命名、不同数据库版本和无法一一映射的情况。
7. 形成后续验证清单，包括需要实际查询 UniProt、PDB 或其他数据库的项目；未调用时不得填入假结果。

## 输出格式

- **对象与版本范围**。
- **标识符映射表**。
- **功能和机制证据表**。
- **表达、定位、互作与通路摘要**。
- **结构或变体资料索引**。
- **冲突、歧义和待核验项**。
- **建议的实验或计算验证方向**。

## 质量检查

- 所有标识符带物种和版本语境。
- 不把基因名称、蛋白名称和数据库 accession 混为一谈。
- 不虚构 UniProt、PDB、NCBI 或其他数据库记录。
- 预测结果不能写成实验已证实功能。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
