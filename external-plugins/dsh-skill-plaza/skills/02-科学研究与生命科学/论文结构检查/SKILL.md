# 论文结构检查

## 目标

从整体论证而非单句润色角度检查论文，找出研究问题、方法、结果和结论之间的断裂、重复与错位，并给出可执行的重组建议。

## 工作流程

1. 提取论文的一句话主张、研究问题、主要贡献和目标读者。
2. 为摘要、引言、方法、结果、讨论和结论建立功能清单。
3. 检查研究问题是否在方法中得到操作化、在结果中得到回答、在讨论中被适度解释。
4. 检查结果顺序是否服务于主线，图表与正文是否重复或缺少解释。
5. 检查讨论是否区分结果、解释、与既有研究比较、限制和意义。
6. 识别过度主张、因果越界、未支持结论和新结果混入讨论的问题。
7. 提供最小修改版和较大重构版，标明改动影响。

## 输出格式

- **论文主线摘要**。
- **章节功能检查表**。
- **重大结构问题**：位置、影响、修改建议。
- **问题—方法—结果—结论对齐矩阵**。
- **建议目录或段落顺序**。
- **过度主张与缺失限制**。
- **修改优先级清单**。

## 质量检查

- 不补造数据、实验、引文或未发生的方法。
- 结构建议保留作者真实贡献，不为了“更像论文”改变研究事实。
- 区分结构问题、语言问题和科学有效性问题。
- 引用具体章节或段落，避免空泛评价。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
