# 文献检索策略

## 目标

为研究问题设计可复现、可迭代的文献检索方案。默认只生成检索策略和记录模板；除非确实调用并获得数据库结果，否则不得声称已经检索。

## 输入要点

确认主题、研究问题、学科、时间范围、语言、文献类型、目标人群或系统、已知关键论文，以及检索用途（探索性、叙述性综述、系统性综述等）。

## 工作流程

1. 用适合领域的问题框架拆分概念，例如 PICO、PEO、SPIDER 或“对象—现象—方法—结果”。
2. 为每个概念列出同义词、缩写、旧称、拼写变体、上位词和受控词表候选。
3. 根据学科建议数据库组合，并说明每个数据库的覆盖价值；不能把建议数据库写成已查询数据库。
4. 构建布尔检索式：概念内用 OR，概念间用 AND，谨慎使用 NOT、字段限定、截词和邻近运算符。
5. 设计高召回初筛、精准补充、引文追踪和灰色文献策略。
6. 规定纳入排除标准、去重规则、筛选流程、检索日志和更新日期。
7. 用若干已知关键文献做理论上的灵敏度检查；没有实际结果时仅说明验证方法。

## 输出格式

1. **检索目标与问题框架**。
2. **概念词表**：自由词、受控词候选、排除歧义。
3. **数据库建议及理由**。
4. **数据库适配检索式草稿**。
5. **筛选与去重规则**。
6. **补充检索策略**。
7. **检索日志模板**：数据库、平台、日期、完整检索式、筛选条件、结果数。
8. **执行状态声明**：明确“仅设计”或列出真实执行证据。

## 质量检查

- 不编造命中数量、论文、DOI 或数据库字段。
- 不把搜索引擎结果等同于系统数据库检索。
- 检索式保留完整括号和字段说明。
- 给出过宽、过窄时的可操作调整方法。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
