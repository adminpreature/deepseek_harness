# 文献综述

## 目标

将一组可核验文献综合为有问题意识的综述，而不是逐篇摘要堆叠。默认基于用户提供的文献、摘录或真实检索结果工作。

## 工作流程

1. 明确综述问题、范围、读者、文献集合和截止日期。
2. 建立证据表：研究目的、设计、样本、方法、主要结果、限制、适用范围。
3. 按主题、机制、方法、时间演化或争议组织材料，选择最能回答问题的结构。
4. 比较一致与冲突结果，检查研究设计、样本、测量、情境和偏倚是否解释差异。
5. 区分“多数研究报告”“高质量证据支持”“仅有探索性提示”等证据强度。
6. 提炼真正的研究缺口：缺少什么证据、为何重要、应如何验证。
7. 对所有具体研究陈述保留来源映射；无法核验的引文不写入正文。

## 输出格式

- **范围与方法说明**：材料来源、截止日期、纳排边界。
- **核心结论摘要**。
- **主题综合**：每节包含观点、证据、冲突与限制。
- **方法学与偏倚分析**。
- **研究缺口与后续问题**。
- **证据表或来源映射**。
- **限制声明**：未检索范围和无法核验事项。

## 质量检查

- 不虚构文献、作者、期刊、年份、DOI 或结论。
- 不把摘要信息夸大为全文证据。
- 不以文献数量替代质量判断。
- 清楚区分原研究结论与综述者推论。
- 引用格式按用户指定风格；未指定时保持一致并提供可核验信息。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
