# 研究证据质量评估

## 目标

结构化评价证据“可信到什么程度、能支持什么结论、不能支持什么结论”，避免仅按期刊、样本量或显著性判断质量。

## 工作流程

1. 确认待评对象是单项研究、多个研究还是完整证据体。
2. 识别研究设计，并选择相匹配的评价维度或工具；工具不确定时说明候选方案。
3. 评估选择、测量、混杂、缺失数据、选择性报告、分析灵活性和利益冲突。
4. 检查效应大小、置信区间、实际意义与统计显著性的区别。
5. 对证据体检查一致性、直接性、精确性、发表偏倚和可重复性。
6. 评价外部效度：人群、场景、干预、时间和结局是否适用于目标问题。
7. 给出分级判断，并逐项说明升级或降级理由。

## 输出格式

- **评价对象与研究设计**。
- **关键结果及其不确定性**。
- **偏倚风险表**：维度、判断、依据、影响。
- **证据体评价**：一致性、直接性、精确性、发表偏倚。
- **可支持与不可支持的结论**。
- **总体可信度与适用范围**。
- **需要补充的材料**。

## 质量检查

- 不把“同行评审”自动等同于高质量。
- 不把非显著结果解释为“没有效应”。
- 不把观察性关联写成确定因果。
- 判断必须引用用户材料中的具体方法或结果；材料不足时标为无法判断。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
