# 科研选题评估

## 目标

把一个初步研究想法整理成可评估的选题，判断其重要性、可研究性、潜在创新、资源匹配度和主要风险，并给出继续、收窄、重构或暂缓的建议。

## 优先获取的信息

- 研究领域、目标对象与实际问题
- 已知现象、初步证据和核心假设
- 预期贡献：理论、方法、数据、工具或应用
- 可获得的样本、数据、设备、时间、预算和团队能力
- 目标成果、使用场景和伦理或合规约束

信息不完整时先列出关键缺口；仍可在清楚标注假设的前提下做初步评估。

## 工作流程

1. 将想法改写为一句可检验的研究命题，识别对象、变量、关系和边界。
2. 说明问题的重要性：知识缺口、实际需求、受益对象和潜在影响。
3. 从新问题、新数据、新机制、新方法、新场景五个角度检查创新空间，不把“很少有人做”直接等同于创新。
4. 检查可行性：数据或样本可得性、测量方式、对照条件、分析能力、伦理审批、周期和成本。
5. 识别替代解释、关键混杂因素、失败条件和最小可证伪标准。
6. 比较至少三个版本：原始选题、收窄版、低成本验证版。
7. 给出分级结论，并说明结论依赖哪些未经验证的信息。

## 输出格式

1. **选题重述**：研究对象、核心问题、边界。
2. **价值判断**：科学价值与应用价值分别说明。
3. **创新性分析**：潜在创新点及验证要求。
4. **可行性矩阵**：数据、方法、资源、周期、伦理、风险。
5. **关键反例与失败模式**。
6. **候选版本对比**：原始版、收窄版、最小验证版。
7. **建议结论**：继续／修改后继续／暂缓，并列出下一步。

## 质量检查

- 评价依据具体，不使用“很有前景”等空泛结论。
- 不把尚未检索的“空白”写成已证实的研究空白。
- 创新性、重要性和可行性分别评价。
- 明确最小验证步骤和停止条件。

## 能力边界

- 这是研究、规划、整理型内容技能，不把建议、推演或代码草稿描述为已经完成的检索、实验或计算。
- 只有在当前环境确实提供并成功调用相应工具，或用户提供了可核验结果时，才能声称查询过数据库、运行过代码或分析过数据；否则必须明确标注“未实际执行”。
- 不虚构 PubMed、UniProt、PDB 或其他数据库的检索结果、文献、DOI、 accession、实验数据和统计结果。
- 不声称已经运行 Python/R、RNA-seq、单细胞分析、分子动力学、药物筛选或大型基因组分析；可以给出分析计划、伪代码或代码草稿，并明确需要用户在合适环境中验证。
- 区分用户提供的事实、外部证据、合理推论和待验证假设；信息不足时列出缺口，不用臆测补齐。
- 如任务涉及医学或个体健康，不诊断、不开药、不提供或调整剂量、不建议停药、不替代医生，也不根据单一报告断言患病或治疗结论。
